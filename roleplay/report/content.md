本实验面向给定人物画像与对话历史的中文角色扮演续写任务，复用 CharacterEval 的角色条件构造与评测思路，不训练模型。对固定 40 条样本比较 GLM、Qwen、GPT 三种服务商模型，并对最终候选开展画像和提示词两种消融。根据可运行性、上下文承接和事实边界的定性核查，选择 GPT-6 Astra 的结构化角色提示，生成并验证全部 571 条回答。实验记录区分实际批次账单、单条分摊估计和未知费用预留。最终文件包含 {{final_records}} 个唯一 ID、{{final_bytes}} 字节，已通过严格格式校验；全部实验已确认费用 {{total_cost}} 美元。由于尚未获准向 OJ 提交，本文不报告未取得的 CharacterRM 分数，也不把定性案例判断解释为显著性能提升。

# 实验目标与数据
本课程任务要求模型成为指定人物，读取角色资料和已有对话，给出该人物接下来的中文回复。任务不是概括故事、回答有关作品的知识问答，也不是一次生成完整剧本。对同一情境可能存在多种合理台词，因此本实验优先考察回答是否承接最后一轮、是否维持人物行为与语言习惯，以及是否把未出现的剧情误当作既定事实。

数据包中的 test_data.jsonl 虽以 jsonl 为扩展名，实际是完整 JSON 数组，必须整体解析，不能逐行当作独立记录。数据包含 571 条样本、571 个互不重复的整数 ID，涉及 77 个角色和 24 部作品。人物画像文件共有 78 个对象，覆盖测试集全部目标角色；多出的画像不构成额外测试样本。每条输入包括 id、role、novel_name、context，其中 context 保留原始多轮对话与动作描写，不截取 README 中的示例片段。

指标映射文件是 JSON 对象，每个值是若干“英文指标名、中文指标名”二元列表。全量展开得到 1005 个评分项，12 个指标的样本数并不相等。ID 6367、952、4584、4879 没有映射，但课程要求提交全部 571 条，因此不以能否评分为由删掉这些记录。该差异也意味着不能把所有展开评分项直接求平均后冒充 OJ 的 Average。

上下文字符数最小为 6，中位数为 155，90% 分位数为 449，最大为 1237。按默认分隔符、ensure_ascii=False 序列化画像后，每条样本对应画像的字符数中位数为 839，最大为 2579。这里统计的是字符而非 token；模型分词和供应商模板可能进一步改变计费用量。三个源文件均记录 SHA256，任何实验输出都以原始 ID 匹配，源数据未作改写。

# 研究基础与评测口径
Tu 等提出的 CharacterEval 为中文角色扮演对话提供人物画像、情境数据和细粒度评估指标，并构建 CharacterRM 评估模型 [1]。本实验复用其“按角色查画像、结合历史生成回复、按样本适用指标展开评估”的基本流程。官方 get_response.py 展示了角色条件对话输入，transform_format.py 将回答按指标展开，compute_score.py 按维度求平均。课程数据规模及提交接口与官方完整任务不同，因此不直接照搬论文榜单数字。

课程 OJ 返回 Fluency、Coherence、Consistency、Exposure、Accuracy、Hallucination、Behavior、Utterance、Humanlikeness、Communication_skills、Diversity、Empathy 十二项基础评分。系统先计算各维度的适用样本均分，再将十二个未舍入维度均分等权平均得到 Average。课件介绍的第四类 MBTI 人格回测不出现在本课程 README 指定的这十二项返回字段中，不能额外混入总分。

Ruangtanusak 等在 CPDC 2025 的工具增强角色对话任务中研究角色提示、自动提示优化及规则式提示，提出人物卡与场景契约的组合 [2]。本实验借鉴人物身份、对话意图、关系和输出边界的明确约束，不引入其工具调用组件，也不将该论文在其他基准上的得分移作本任务成绩。对于短台词续写，避免过度铺陈比搭建复杂代理系统更符合课程目标。

Peng 与 Shang 将角色逻辑表示为带条件判断的可执行结构，突出场景条件与人物决策之间的联系 [3]。本实验只把这一思想转化为提示中的场景判断顺序，不部署完整条件函数或有限状态机。三项研究提供的是设计依据，并不能替代本地实验。报告中的模型选择来自实际输出审阅与运行记录，而非模型名称、外部榜单或“更新模型必然更强”的假设。

# 角色条件与提示方法
每条样本独立处理。首先以 role 在人物画像字典中查找完整对象，再将画像以合法 JSON 字符串序列化，与作品名、目标角色和完整 context 放入用户消息。系统消息规定生成目标和输出边界。历史中的角色名称、引号与括号都作为被续写的材料，而不是重新定义系统规则的指令。生成当前样本时不会插入其他样本的预测结果，从而避免跨样本信息污染。

采用三种输入条件。No Profile 只有作品名、人物名和完整历史；Baseline 在完全相同的简单系统提示下增加完整人物画像。二者的差异仅是画像是否出现，用于对应老师课件中的画像消融。Structured 仍使用相同画像和完整历史，但替换系统提示，要求模型判断最后发言者、对方意图与情绪、人物关系和当前动机，随后只给出下一轮台词。Baseline 与 Structured 比较的是提示词组织方式，不是画像是否存在。

Structured 的核心约束是优先遵守对话已确立的事实，以角色身份和价值取向自然回应，必要时配合简短动作描写；不机械拼贴名言，不随意增加背景故事、关系或外部事实，不展示中间推理。通常将回复引导在 20 至 100 字，但不按字符数强制截断，以免切掉完整语义。人物本来寡言或场景需要时，可以更短；这类长度分布只是运行统计，不是质量分数。

输出层只接受文本。程序取解码后第一行、清除首尾空白，并仅在开头出现目标角色名加冒号时移除该前缀。空串、ERROR、过长文本、模型报告的截断或过滤状态不作为成功答案。原始响应和 finish_reason 在清理前保存，避免把后处理后的简洁文本误认为模型原来就遵守了所有要求。如果最终回答只有动作而没有发言，格式检查可能通过，但仍需定性审阅发现这一语义问题。

不设置复杂检索、知识库和多轮自我修正机制。当前测试样本很短，完整画像和完整历史可直接送入接口；额外检索可能引入人物故事后期的信息，反而与当前场景冲突。不训练新模型，不改变公开测试集，也不将 id2metric 中的评分指标逐条输入生成模型，以降低针对单项指标作机械迎合的风险。

采样使用固定种子 20261118，将角色分组后打乱角色顺序，每个角色先取一条，再补充剩余样本。40 条比较集因此包含 40 个不同角色，三种模型与两项消融使用完全相同的 ID 集合。种子仅控制样本选择，不等同于模型生成种子；API 端存在随机性，单次结果不能解释为稳定的因果改进。

# 开发环境与可靠调用
实验在 Linux 本地运行，Python {{python_version}}，OpenAI 兼容客户端 {{openai_version}}，HTTP 客户端 {{httpx_version}}。本机显卡为 NVIDIA GeForce RTX 4060 Laptop GPU，显存 8GB。官方 CharacterRM 权重约 26.5GB，无法直接按官方半精度 GPU 流程装入本机，因此没有伪造本地奖励模型分数，也未为本课程额外训练评估器。

AINet Hub 的 /v1/models 鉴权接口返回了 glm-5.3-flash、qwen3.8-max、gpt-6-astra-medium 等实际可请求的目录 ID。但这些是代理展示的别名，不能独立证明其背后模型身份与版本。主域及常见子域的 HTTPS 接入未能建立连接；经用户明确同意，实际调用使用 http://ainet-hub.com/v1，并保持禁止跟随重定向。密钥只从本地环境变量读取，不进入命令行、版本库或报告。HTTP 传输仍存在监听和身份验证风险，这一限制没有因获得用户同意而消失。

供应商未公开可核验的费率表，后续按用户要求不再围绕价格查询耗时，改为读取 /v1/usage 的美元账单。串行请求以同一模型调用前后的 actual_cost 差额记费；小批并发按请求数增量和批次美元差额一起核对。只有增量等于本批请求数才结算，出现并发污染或账单未更新时保留预算并停止。批次总额是实际账单，单条均分仅供汇总，不能当作每条的独立发票金额。

SQLite 账本在发请求前以事务预留预算，全局上限 100 美元，同时限制单实验额度。超时、429、5xx 等未知结果不能自动按零元处理；有限重试前也要重新预留。收到 token usage 后，即使回答为空或被截断，也先保存原文并记账，再决定是否接受。HTTP 400 不盲目重试。两个关闭思考参数的 400 请求仍保留 {{unknown_reserve}} 美元未决预留；本文将其与已确认费用分开列示。

每个 run-id 的 manifest 固定模型、地址、完整提示词、样本 ID、画像和测试集哈希、生成脚本哈希及解码参数。配置变化使用新的 run-id，不能把不同实验混在一次断点续跑里。{{test_count}} 项离线测试覆盖源数据、清理、严格校验、账本、接口参数、模拟异常、批次结算和恢复，普通模式与 python -O 均通过。测试使用临时模拟答案，不进入正式提交文件。

# 模型比较与两项消融
真实 Smoke Test 暴露了接口细节。GLM 首次请求耗尽 768 个输出 token，最终台词为空，费用仍计入实验；尝试关闭思考得到 400，供应商明确提示该模型始终思考，支持 low、high、max。提高输出上限仍在少数样本出现截断；显式使用 low 后完成了 40 条。Qwen 在默认思考条件下的一组运行同样发生截断，保留 19 条有效输出后停止；切换 low 后完成 40 条。失败组没有被删去或伪装为完整实验。

正式模型比较均使用 Structured、相同 40 条样本、4096 输出 token 上限和 low 思考强度。GLM、Qwen 显式传 temperature=0.7，GPT 未传该参数而采用服务商默认；这一差异需要在解释结果时保留，不能把比较说成对模型内部一切因素的严格控制。表中输入与输出 token 是服务商响应口径，包含服务商可能加入的模板或隐藏计算，不能简单把 token 更多等同于台词更长。

# 总结与局限
本实验完成了从原始数组解析、人物条件构造、服务商接口校验、固定样本比较、两项消融到 571 条文件生成的可复现流程。主要实践价值在于完整保留角色资料与历史、把短轮输出约束落到可检查的规则，并将失败请求和未知费用纳入预算，而不是提出新模型或复杂代理算法。代码审查发现的指标列表解析错误、断言在优化模式失效、断点配置不完整及失败漏记账等问题，均有相应测试覆盖。

结果解释有三项边界。首先，40 条虽然覆盖不同角色，但每个角色只有一条，无法反映所有场景，更不是多次随机重复实验。其次，本实验没有独立人工标注或本地 CharacterRM 评分，定性抽查由 AI 辅助完成，不可称作盲测人类偏好或奖励模型评测。最后，模型是供应商别名，内部模板、分词和版本可能变化，保存 manifest 与原始响应也不能保证未来完全复现相同句子。

OJ 十二项评分及 Average 目前均未取得。正式上传需另行确认提交配额、截止时间和用户授权，不能因为本地 JSON 校验通过就宣称已完成线上评测。获得 Success 后应将真实十二项指标、Average、提交时间和文件哈希补入结果记录，再分析各维度差异。本文的最终文件和本地验收结论可以独立核查，但不替代这一步线上评价。

本次实现也表明，短句角色扮演的主要难点不是拼接更多背景，而是区分“画像中知道的故事”和“当前场景已经发生的事实”。后续如果继续改进，应先针对已观察到的虚构引语、纯动作输出和关系泛化做有限验证，再考虑额外复杂机制。当前方案保持可解释、可审计且未训练新模型，适合课程作业的复现范围。
