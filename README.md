中文角色扮演对话评测
一、任务目标

本任务要求你的模型根据角色资料和对话历史，生成指定角色接下来的一句中文回复。

每条样本会告诉你需要扮演谁，以及此前发生了什么对话。你需要让模型以该角色的身份回答：既要回应当前话题，也要符合角色的知识、性格、行为和说话方式。可以在回复中使用括号描述动作、表情或语气。

你需要先在本地生成回答，再将结果保存为文件上传至 OJ。系统会返回 12 项基础评分和综合分 Average。所有评分均为 1～5 分，越高越好。

本题使用固定的 571 条测试样本。所有参赛者使用相同的数据，不要自行更换样本或重新抽样。
二、数据文件与字段

请点击此处下载需要使用的数据文件。
文件 	内容 	用途
test_data.jsonl 	样本编号、目标角色、作品名称和对话历史 	为其中的每条样本生成回答
character_profiles.json 	按角色名称组织的角色资料 	根据样本的 role 字段查找角色背景
id2metric.jsonl 	每条样本需要评测的指标 	由系统用于评分，无需修改或上传

读取方式：本题的 test_data.jsonl 内容是一个完整的 JSON 数组，虽然文件扩展名为 .jsonl，仍应使用 json.load() 读取。character_profiles.json 和 id2metric.jsonl 的内容是 JSON 对象。

test_data.jsonl 中每条样本包含以下字段：
字段 	含义
id 	样本的唯一编号，提交时必须保留
role 	模型需要扮演的角色
novel_name 	角色所属的作品名称
context 	已有对话，包含说话者及可能出现的动作描写

下面是一条样本的节选，仅用于说明字段。生成回答时必须读取文件中的完整 context，不能只使用此处展示的片段。

{
  "id": 10453,
  "role": "佟湘玉",
  "novel_name": "武林外传",
  "context": "佟湘玉：（撒娇）哎呀，说吗说吗，这么简单的问题，需要想这么久？"
}

角色资料通过角色名称查找：

profile = character_profiles[example["role"]]

资料可能包含姓名、身份、背景、性格、经历和代表性话语。请结合这些信息构造模型输入。提交时只需上传样本编号与生成的回答，不需要上传角色资料或对话历史。
三、回答要求

对每条样本，按照以下步骤生成回答：

    读取 role，确定模型需要扮演的角色。
    从 character_profiles.json 中读取对应角色资料。
    使用该样本的完整 context 作为对话历史。
    生成目标角色接下来的中文回复，并保存到 model_output 字段。

每条样本独立处理。不要将其他样本的预测回答替换进当前样本的对话历史。

回复应当切题、自然，并保持角色的一致性。例如，可以使用“（皱了皱眉）……”这样的动作与台词组合，但不要求所有回答都包含动作描写。

请将每条完整回答写在一行内。系统只评估 model_output 解码后的第一行，后续行不会参与评分。第一行去除首尾空白后如果为空，或等于 ERROR，会被拒绝。

这一规则针对的是回答字符串内部的换行。JSON 文件本身可以为了排版而分成多行。
四、提交文件格式
推荐格式：JSON 数组

将生成结果保存为 UTF-8 编码的 .json 文件。数组中的每个对象只需包含两个字段：

    id：对应测试样本的编号。
    model_output：模型生成的回答，必须是字符串。

[
  {
    "id": 10453,
    "model_output": "（略一思索）此事还需问清原委，不能仓促下结论。"
  },
  {
    "id": 433,
    "model_output": "（认真听完）你先别急，且把事情的经过说清楚。"
  }
]

以上回答为虚构的格式示例，不是参考答案。只包含这两条记录的文件不能作为完整提交。请根据实际测试数据生成自己的全部回答。

系统也支持 .jsonl 文件，每行写一个完整的 JSON 对象：

{"id":10453,"model_output":"（略一思索）此事还需问清原委，不能仓促下结论。"}
{"id":433,"model_output":"（认真听完）你先别急，且把事情的经过说清楚。"}

六、评分指标与综合分

系统根据角色资料、对话历史和你的回答，使用 CharacterRM 对适用的指标进行评分。每项分数均在 1～5 分之间，全部指标都是越高越好。
维度 	返回字段 	主要评估内容
语言流畅度 	Fluency 	中文是否通顺、自然，是否存在明显语法问题
对话连贯性 	Coherence 	是否回应当前话题，是否与上下文相关
对话一致性 	Consistency 	是否与对话中已经出现的信息或先前说法矛盾
角色知识表达 	Exposure 	是否自然地表达与角色及当前情境有关的知识
角色知识准确性 	Accuracy 	所表达的知识是否符合角色的身份、背景和资料
避免知识幻觉 	Hallucination 	是否避免编造事实，是否尊重角色应有的知识边界
行为一致性 	Behavior 	动作、表情和语气是否符合角色及当前场景
言语风格一致性 	Utterance 	用词、表达方式和说话习惯是否符合角色
类人程度 	Humanlikeness 	是否像场景中真实人物的自然交流，角色表现是否可信
交流技巧 	Communication_skills 	是否能得体、有效地处理对话中的人际互动
表达多样性 	Diversity 	表达是否丰富，是否避免机械重复和空泛套话
共情能力 	Empathy 	是否理解并恰当地回应对方的情绪

不同样本适合评测的指标不同，由系统统一决定。你不需要在提交文件中指定指标，也不需要提交参考答案或分数。

评分先对每个维度所对应的样本分别求平均，再计算综合分：

Average = 12 个基础维度均分之和 ÷ 12

每个维度在 Average 中的权重相同。

结果共包含 13 个数值字段：12 项基础评分和 Average，返回时统一四舍五入到小数点后三位。Average 由未舍入的各维度均分计算后再舍入，因此可能与页面上三位小数重新计算出的平均值略有差别。

评测模型一次最多读取 4096 个 token，其中包含角色资料、对话历史、回答和指标信息；超过时保留末尾部分。token 数与字符数不同，因此即使回答没有超过 20000 字符，也不意味着全部评分输入都能完整保留。建议回答简洁、切题，避免无关的长篇内容。

总次数限制和每日次数限制按“每位用户、每道题目”分别计算，具体限额以提交页面显示为准；Unlimited 表示该项不限次数。

    只有 Success 的提交消耗次数。
    Pending 和 Running 的提交会暂时占用名额。
    Failed 不消耗成功提交次数，并会释放占用的名额。
    每日限额按 Asia/Shanghai（北京时间）零点重置，以提交日期为准。跨天完成的任务仍归属于提交当天。
    超过题目截止时间后不能继续提交。
